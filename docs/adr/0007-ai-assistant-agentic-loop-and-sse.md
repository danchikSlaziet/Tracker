# ADR 0007: AI-ассистент с агентным циклом (Function Calling) и SSE стримингом

## Статус
Принято (Accepted)

## Контекст
Приложению для учёта личных финансов требовался интеллектуальный финансовый советник, способный отвечать на вопросы пользователя на естественном языке (анализ трат за период, динамика расходов по категориям, баланс, поиск операций).

Передача всех транзакций пользователя напрямую в системный контекст LLM на каждый запрос имела критические недостатки:
1. Ограничение контекстного окна и высокий расход токенов.
2. Утечка лишних конфиденциальных данных.
3. Низкая скорость ответа и риск ошибок при подсчётах в больших массивах данных.

## Решение
Реализован **AI-ассистент на базе агентного цикла (Agentic Loop / Tool Use)** с потоковой передачей данных (Server-Sent Events):

1. **Модель**:
   - Использование открытой модели **Qwen 2.5** через высокоскоростной API **Groq**.

2. **Агентный цикл (Function Calling)**:
   - Модель получает описание доступных инструментов: `get_summary`, `get_spending_by_category`, `get_monthly_trend`, `get_recent_transactions`.
   - При необходимости модель инициирует `tool_calls`. Бэкенд выполняет точные агрегированные запросы в PostgreSQL через Prisma (`aggregate`, `groupBy`) и передаёт структурированный результат обратно модели.
   - Защита от зацикливания: глубина цикла ограничена параметром `maxSteps = 5`.

3. **Стриминг и UX**:
   - Бэкенд транслирует события через протокол **Server-Sent Events (SSE)** (`POST /api/assistant/chat`).
   - На фронтенде чтение потока организовано через библиотеку `@microsoft/fetch-event-source` с поддержкой `credentials: 'include'` для аутентификации по `httpOnly` JWT-кукам.
   - Во время работы инструментов пользователь видит промежуточный статус выполнения (например, *«Анализирую расходы по категориям...»*).
   - Рендеринг текста в реальном времени с поддержкой Markdown (`react-markdown`).

4. **Архитектура состояния (FSD + Zustand)**:
   - Глобальный UI-стейт сессии чата вынесен в Zustand Store (`assistantStore.ts`), что обеспечивает сохранение диалога при закрытии модального окна и навигации по страницам приложения в рамках сессии.

## Последствия
### Положительные:
- Высокая точность финансовой аналитики благодаря выполнению вычислений на стороне PostgreSQL, а не в контексте LLM.
- Минимальный расход токенов за счёт передачи только агрегированных результатов.
- Мгновенный отклик интерфейса за счёт посимвольного стриминга ответа.
- Безопасность: модель не имеет прямого доступа к базе данных и работает исключительно через валидированные функции.

### Отрицательные / Компромиссы:
- Зависимость от доступности внешнего сервиса (Groq API).
- Необходимость поддержания схемы валидации инструментов при изменении модели данных.
