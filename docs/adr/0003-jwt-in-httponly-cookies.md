# 3. JWT в httpOnly-куке

* Статус: Принято
* Дата: 2026-07-05

## Контекст и проблематика
Токен сессии нужен на каждом запросе. Если положить его в `localStorage`, любой скрипт на странице прочитает его через `localStorage` и унесёт.

## Принятое решение
JWT лежит в куке:
- `httpOnly: true` — `document.cookie` её не видит;
- `secure: true` только при `NODE_ENV=production`;
- `sameSite: 'strict'` — браузер не прикладывает куку к запросу с другого сайта.

Axios ходит с `withCredentials: true` и сам куку не читает. Срок куки 7 дней. В JWT только `{ userId }`.

На API origin задан явно: `CORS_ORIGIN`, локально `http://localhost:5173`. `cors()` без origin стоит лишь на `/api/uploads`, оттуда отдаются картинки.

## Альтернативы
1. **`localStorage`.** Не нужна настройка CORS, но токен доступен любому скрипту на странице.
2. **Сессия в базе, в куке только её id.** Токен некуда украсть, но каждый запрос читает сессию из Postgres, а выход должен эту запись удалять. JWT проверяется без похода в базу.

## Последствия
### Плюсы
- Скрипт не читает токен и не может унести его на другой компьютер.
- Чужой сайт не отправит запрос с этой кукой. Отдельный CSRF-токен не нужен.

### Минусы
- Скрипт, который уже выполняется на странице приложения, может вызывать API от имени пользователя: браузер приложит куку сам.
- До истечения 7 дней сервер не может отменить токен: подпись JWT проверяется без записи в базе.
